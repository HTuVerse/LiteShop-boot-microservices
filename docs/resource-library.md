# 平台资源库与文件存储

## 上线顺序

1. 备份 `liteshop_file`、`liteshop_config`、`liteshop_user` 数据库及原本地上传目录。
2. 按顺序执行 `sql/vertical-split/75_resource_library.sql` 和 `sql/vertical-split/76_storage_drivers.sql`。前者补齐资源库字段、文件夹和超级管理员菜单；后者添加存储字段与配置快照，并把历史记录绑定到升级前的配置。
3. 部署 config、file、restaurant、user 服务及管理端。文件服务的 HTTP multipart 上限须与后台的单文件上限相容；同时核对 Nacos `liteShop-file-service` 配置，避免其旧的 20 MB 限制覆盖应用配置。
4. 超级管理员在网站配置的“文件配置”中选择 Local、MinIO、阿里云 OSS 或七牛云，保存后使用“测试已保存的连接”。该检查验证当前驱动的存储位置；还应从实际浏览器打开一张公开图片并验证一个私有签名链接。

文件记录保存驱动编号、对象 Key、Bucket、可见性及上传时的配置快照 ID。切换默认驱动仅影响新文件；旧文件仍使用原驱动和原配置快照。不要删除历史 Bucket、域名、凭据或本地目录。切换配置不会迁移文件，更不能批量改写 `storage_type` 冒充迁移。若以后迁移，应逐件复制、核对内容及业务引用，最后以可回滚的方式更新记录和域名映射。

## 公开与私有资源

公开图片建议使用独立的 HTTPS 资源域名，例如 `https://static.example.com/`。对象 Key 是 `yyyyMMdd/随机UUID.扩展名`，公开 URL 由资源域名和 Key 组成并持久保存在文件记录中。前台可直接加载该 URL，不需要由业务服务转发流量。公开资源可由 Nginx 或 CDN 设置缓存；由于 Key 不复用，适合长期缓存。网站和小程序应使用上传接口返回的 URL 或资源接口提供的 URL，不要自行拼 Bucket、Endpoint 和 Key。

MinIO 与阿里云 OSS 使用彼此隔离的公开、私有 Bucket；七牛云在启用私有资源前也必须配置单独的私有 Bucket 和对应的私有访问域名。公开入口只能映射公开 Bucket，**不得**将私有 Bucket 匿名开放或挂在公开资源域名下。修改资源权限时服务会在两个位置之间复制并撤销旧对象，不能只改数据库字段。已公开文件转私有后，仍须清理 CDN 缓存；已经下载到浏览器或第三方的副本无法收回。私有文件不保存永久 URL；超级管理员经鉴权可申请五分钟签名 URL，本地私有文件走鉴权下载接口。需要更多角色访问时，应在资源接口中增加相应业务授权规则。大文件与视频优先通过对象存储的直达地址访问，外部网关应允许 Range 请求。

资源删除与公开转私有之前，文件服务会向配置、餐饮、用户服务查询已知业务引用。任一服务不可达时操作中止。重命名只改变显示名，不改变对象 Key 和已引用的公开 URL。文件夹只是资源库分类，不改变存储路径。历史数据若缺少可推导的随机 Key，删除、下载或修改权限需要先做明确的数据修复。

## 远程宝塔 MinIO

- 将 MinIO **API** Endpoint 配成后端可达的 HTTPS 地址；它与 MinIO 管理控制台是两个入口。管理控制台应限制访问范围。后端运行在本地开发机时，也必须能通过网络访问 API Endpoint。
- 将“浏览器可达 API Endpoint”配为浏览器可访问、且反向代理到同一 MinIO API 的 HTTPS 地址。它用于私有对象签名，域名和请求路径必须与实际浏览器请求一致。此入口应保留签名查询参数，且私有 Bucket 仍禁止匿名访问。
- 将“公开资源域名”单独指向公开 Bucket，例如 Nginx `static.example.com` 转发到 MinIO 公开 Bucket；配置只填写 URL 前缀，不要填写管理控制台地址。公开 Bucket 需要正确的只读匿名策略，私有 Bucket 不能配置匿名策略。
- 为应用创建独立的最小权限凭据，允许对上述两个 Bucket 执行所需的上传、查询、复制和删除操作；不要使用 MinIO Root 凭据。通过后台密钥输入框配置，已保存密钥只回显“已配置”状态。配置数据库和加密密钥也应备份。
- MinIO 数据目录挂载到服务器持久化磁盘，做好磁盘容量、定期备份和恢复方案。若启用浏览器直传或跨域预览，应按使用的域名配置 CORS；单纯的 `<img>` 展示通常不需要跨域读取权限。

本实现只提供适配代码和配置入口，不会连接或修改真实服务器。公开域名、证书、Nginx、Bucket 策略及 MinIO 持久卷需在实际部署环境配置。

## 阿里云 OSS 与七牛云

阿里云 OSS 使用其原生 Java SDK，需填写区域 Endpoint、独立的公开/私有 Bucket、公开自定义域名及 Access Key。私有访问由 SDK 生成临时签名 URL。七牛云延续历史驱动编号 `1`，新配置也可选择七牛；私有空间需配专用访问域名以生成签名 URL。两者都应给公开域名配置 HTTPS，并核对跨域、缓存、权限及浏览器实际可达性。

Local 模式使用平台配置的上传根目录和公开基础地址；私有文件位于根目录下的 `.private`。Nginx 若直接映射本地目录，必须拒绝 `.private` 路径。Local 适合开发与兼容历史文件，服务器部署时应将根目录挂载持久卷。
