# 操作权限说明

菜单权限继续控制页面访问和该页面的基础查询；写入操作使用独立权限码。角色名称及普通业务角色编码不参与操作接口放行判断。平台超级管理员保留显式豁免。租户、门店数据范围及对内置管理员账号的保护仍然生效。

例如 `system:user` 允许查看用户页面，`system:user:edit` 允许编辑，`system:user:delete` 允许删除。`system:user:assign-role`、`system:user:level`、`system:user:reset-password`、`system:user:recharge` 分别控制角色分配、等级调整、密码重置和充值。编辑接口同时校验请求中实际变更的角色和等级，不能通过提交额外字段绕过单独授权。

角色权限树使用真实权限 ID，分别标出菜单、操作和接口。勾选菜单不会自动勾选操作；勾选操作会在保存时补齐所属页面和上级目录，前后端均执行此规则。菜单名称和目录位置可以调整，已接入代码的权限码必须保持一致。

前端 `useAuth().hasAuth(code)`、`v-auth="'完整权限码'"` 和 `ArtButtonTable` 的 `auth` 属性读取后端已授予的权限。多个权限码表示任意一个满足即可，用于收银等共享操作。前端只提供交互控制，后端通过 Sa-Token 独立校验。操作权限变化后，后端下一次权限查询读取最新授权；其他已打开的客户端需刷新页面更新按钮显示。

订单和收银操作分别划分结算、退菜、赠菜、折扣、取消、加菜、状态和打印。其他模块包括门店、餐桌、分类、菜品规格、打印机、模板、优惠券、抽奖、会员等级和配置。编辑请求中变更上下架／启用状态、默认模板以及收银中的赠菜和折扣，也会检查对应操作权限。

共享页面所需的分类、打印机、模板下拉查询允许来自对应使用页面的权限；这些只读授权不会授予新增、删除等写入操作。自定义角色仍需配置其门店数据范围。

## 数据库升级与发布

1. 备份用户数据库；确认已有多租户结构和 01～15 中对应的菜单补丁。
2. 在 `liteshop_user` 执行 `docs/sql/16_operation_permissions.sql`。脚本先校验父菜单、权限类型、ID 冲突，失败时回滚。
3. 发布配套后端及前端。不要单独发布前端或只发布后端：旧角色尚无操作权限记录时会看不到按钮或被拒绝操作。
4. 角色管理 → 分配权限，取消不需要的操作，并用普通自定义角色核验。

首次升级只给新建的操作权限复制原父菜单的角色授权，保留升级前能力；不会自动减少既有角色权限。重跑跳过已有操作权限，不恢复后来撤销的授权。SQL 文件不会自动连接或修改数据库。

权限目录保存在 `docs/operation-permissions.json`，运行 `node scripts/generate-operation-permissions.mjs` 可重新生成升级脚本。新增角色只需配置已有权限；新业务能力仍需同步登记权限码、后端校验和前端操作控件。

## 验证

前端：`npm run typecheck`、`npm run test:integration`、`npm run build`。

后端：`mvn test`。`OperationPermissionTest` 实际调用 Sa-Token 注解校验器，验证菜单权限不能写入、自定义角色按权限放行、ADMIN 无隐式操作权限、SUPER_ADMIN 豁免、撤销立即生效、复合字段隔离及结算与退菜隔离。`PermissionAssignmentTest` 验证选择页面不授予按钮、按钮补齐父级及缺失／停用父级拒绝保存。
